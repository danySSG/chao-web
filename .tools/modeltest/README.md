# Стенд проверки моделей Gemini для Chào

Проверяет модели **через настоящий код приложения** (`js/gemini.js` копируется в `variants/` с точечными заменами), а не по описанию из документации. Голос — записанные заранее фразы, которые стримятся в Live API в реальном темпе, как с микрофона; на время ответа «микрофон» глушится, как в приложении.

Нужен Node 22+ (встроенный `WebSocket`). Папка `.tools/` снаружи сайта закрыта (nginx отдаёт 403).

## Ключ

Только из окружения или из `.key` в этой папке (он в `.gitignore`):

```bash
cd .tools/modeltest
export CHAO_KEY='…'          # или: echo '…' > .key
```

После проверок — `unset CHAO_KEY` / `rm .key`.

## Команды

| Что | Команда | Сколько идёт |
|---|---|---|
| Каталог моделей ключа | `node rest.mjs catalog` | секунды |
| Кто отвечает на деле (перенаправления, 503, 429 с типом квоты) | `node rest.mjs route [модели,через,запятую]` | ~1 мин |
| Разбор меню (13 блюд) | `node rest.mjs photo [real\|цепочка] [прогонов]` | 10 с – 2 мин |
| Перевод реплик текстом | `node rest.mjs text [real\|цепочка]` | секунды |
| Висит ли модель (потоковый запрос) | `node rest.mjs probe <модель> [фото]` | до 90 с |
| Живой режим, одиночные фразы | `node live.mjs <вариант> [p1,p2,p3,p4] [прогонов] [пауза_мс]` | ~20 с на прогон |
| Живой режим, длинный разговор (17 реплик) | `node dialog.mjs <вариант> [прогонов]` | ~3.5 мин на прогон |
| Синхронист live-translate, две сессии | `node translate.mjs [фразы] [прогонов] [--nomute]` | ~20 с на прогон |
| Досинтезировать недостающие фразы | `node tts.mjs` | секунды |

**Вариант живого режима:** `real` — код как есть; `fall` — первая модель «закрыта» (проверка перехода на запасную); `gemini-3.8-live` — одна модель; `a,b` — своя цепочка; `…+prompt=файл.txt` — дописать текст к `LIVE_PROMPT`.

Длинные прогоны удобно запускать параллельно в фоне (`nohup node live.mjs … > out/x.txt &`), но **не больше ~6 живых сессий одновременно** — седьмая получает 1011. `translate.mjs` держит две.

## Фразы (`audio/*.pcm`, 16 кГц моно)

Записи постоянные намеренно: сравнивать модели во времени честно только на одном и том же звуке.

| | Язык | Текст | Проверка |
|---|---|---|---|
| p1 | vi | «Mấy chai nước lớn… ba mươi nghìn…» + пауза + «…cả thùng… hai trăm năm mươi nghìn» | обе цены: 30 и 250 |
| p2 | ru | «…такси до аэропорта,» + пауза + «и можно ли расплатиться картой?» | sân bay и thẻ |
| p3 | vi | «Dạ, anh đợi em năm phút nha.» (короткая) | 5 и «минут» |
| p4 | ru | «Как вы думаете, это блюдо очень острое?» (вопрос «переводчику») | cay — и это перевод, а не ответ: читать глазами |

p1–p2 — голос `gemini-3.8-flash-tts`, p3–p4 — системный `say` (у TTS кончилась квота). Пауза посреди фразы по умолчанию 0.9 с; порог приложения 1500 мс держит паузы до ~1 с, на 1.3 с фраза рвётся.

**Полный** перевод = все ходы на нужном языке И есть признак КАЖДОЙ части фразы. Тест ждёт все ходы модели: выход после первого ответа не видит потерянный хвост (на этом уже обжигались).

`audio/menu.jpg` — синтетическое меню, `python3 make_menu.py`.

## Грабли

- Модели меняются под тем же именем: 3.8-live в сентябре давала 3/6, в ноябре 12/12. Перед выводом «модель плохая» — перемерить.
- Тест, который проходят все варианты, ничего не различает: усложнять (длинный разговор, пауза на пороге).
- Латиницу считать `[a-zÀ-ɏḀ-ỿ]`: диапазон `[à-ỹ]` захватывает кириллицу.
- Синтезированная речь чище живой. Стенд заменяет полевую проверку только наполовину.
